## 实用评估

### 什么场景值得用

- **SWE 任务自动化**: 82.1% 的 SWE-Bench 得分意味着从 bug 报告到 patch 的自动化流程可以大规模部署。对于有持续集成需求的团队，这可以显著缩短修复周期。
- **大规模代码重构**: 1M token 上下文使得整个仓库可以在单次 prompt 中加载，无需 chunking 策略。跨文件重构、API 迁移等任务受益最大。
- **高频编码工作负载**: $3/$15 的定价使得团队可以将 AI 编码工具的使用量提升 5 倍而不增加预算。对于日均数百次 API 调用的团队，这是决定性优势。
- **Dev Team 模式适合复杂项目**: 当任务涉及多个模块/文件时，多 agent 并行 + 交叉验证的质量优于单 agent。

### 什么场景不值得用

- **极致推理深度任务**: 对于需要 extended reasoning 的复杂数学/科学问题，Opus 5（如果存在）可能仍更强。Sonnet 5 的定位是"编码性价比之王"，不是"最强推理"。
- **本地部署需求**: 目前 Sonnet 5 仅通过 API / Claude Pro / Vertex AI 提供，不支持本地部署。DeepSeek V4 的开源权重版本可能是更好的选择。
- **对 Anthropic 生态无依赖的团队**: 如果团队已经深度绑定 OpenAI 或 Google 生态，迁移成本可能超过 Sonnet 5 带来的收益。
- **需要五眼联盟以外访问的敏感场景**: 36 氪报道提到 Fable 5/Mythos 5 被出口管制封锁非美国公民，虽然 Sonnet 5 目前仍可用，但地缘政治风险值得留意。
