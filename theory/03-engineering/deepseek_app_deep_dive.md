## 是什么 / 解决什么问题

DeepSeek 自推出以来，在文本推理和代码生成领域建立了强大的竞争力。然而，在多模态领域，它一直落后于 GPT-5、Claude Sonnet、Gemini 等竞品——这些模型早已支持图像理解、视觉问答等能力。2026 年 6 月 18 日，DeepSeek 多模态研究员 Xiaokang Chen 宣布"识图模式"在网页端和 App 端正式上线，标志着 DeepSeek 正式补齐了多模态能力的最后一块拼图。

但这次上线的意义不止于"终于有了图片功能"。DeepSeek 在 2026 年 4 月同步公开的技术报告中，提出了一种名为 **"Thinking with Visual Primitives（以视觉原语思考）"** 的创新框架。

### 核心洞察：参照鸿沟比感知鸿沟更根本

当前多模态大语言模型（MLLMs）的研究主流聚焦于弥合"感知鸿沟"——通过高分辨率图像裁剪、增加视觉 token 数量等手段提升模型对视觉细节的识别能力。但 DeepSeek 团队认为，这忽视了一个更为根本的限制：**参照鸿沟（Referential Gap）**。

自然语言固有的模糊性使其难以对复杂的空间布局提供精确、明确的指引。当模型需要执行涉及严谨空间参照的任务时（比如"图中左上角第三个物体的颜色是什么"），语言链式思维（CoT）的推理链条容易断裂，出现逻辑崩溃。

DeepSeek 的解决方案：将点、边界框等空间标记从单纯的视觉输入元素，提升为推理过程中的"基本思维单元"——模型可以在思考链中直接"指代"图像的具体物理坐标。

## 技术架构拆解

### 从 DeepSeek-VL2 到视觉原语框架：技术演进

DeepSeek 在视觉理解领域已有积累。其开源的 DeepSeek-VL2 模型（MoE 架构，1.0B/2.8B/4.5B 激活参数）已支持视觉 grounding 功能，通过特殊 token 实现物体定位：

```
输入: <|grounding|><image>\n<|ref|>The giraffe at the back.<|/ref|>
输出: <|ref|>The giraffe at the back.<|/ref|><|det|>[[580, 270, 999, 900]]<|/det|>
```

**关键演进**：在 VL2 中，`<|ref|>` 和 `<|det|>` 是输入/输出层的特殊标记；而在"Thinking with Visual Primitives"框架中，这些空间标记被提升为**推理链内部的思维单元**——模型在 CoT 的中间步骤就能直接使用坐标进行推理，而非仅在输入和输出端使用。

### 核心设计决策

| 设计选择 | 具体方案 | 理由 |
|----------|---------|------|
| 视觉原语嵌入推理链 | 将点、边界框等空间标记嵌入 CoT 中间步骤 | 使抽象认知轨迹锚定到图像物理坐标，避免语言模糊性导致的推理断裂 |
| 解决参照鸿沟而非感知鸿沟 | 不依赖高分辨率裁剪，聚焦空间参照能力 | 主流方案提升感知但忽视语言模糊性导致的推理断裂 |
| 紧凑模型 + 低图像标记预算 | 高度优化的架构，视觉标记效率显著高于竞品 | 在保持性能的同时降低计算成本，指向更高效的 System-2 多模态智能 |
| 三模式并列 UI | 识图模式 / 快速模式 / 专家模式 | 用户可按场景选择，识图模式专注多模态理解而非简单 OCR |

## 实战陷阱与避坑指南

### 陷阱 1：低图像标记预算 ≠ 所有场景都好用

DeepSeek 采用"低图像标记预算"策略，这意味着模型在编码图像时使用的视觉 token 数量显著少于竞品。**实战影响**：

- 对于高分辨率图像（如 4K 截图、精细图表），低标记预算可能导致细节丢失。如果你的任务依赖极细粒度的视觉信息（如识别小字体文本、精细设计元素），DeepSeek 识图模式可能不如 GPT-5.4 或 Claude-Sonnet-4.6。
- **应对策略**：在调用 API 前对图像做预处理——裁剪关键区域、放大目标物体、降低分辨率到模型最优输入范围。不要直接丢一张 4K 截图进去。

### 陷阱 2：视觉原语框架对"非空间类"图像任务无额外优势

"Thinking with Visual Primitives"的核心优势在于空间推理和参照。对于以下任务，该框架**不会**带来明显优势：

- 图像分类（猫 vs 狗）—— 纯感知任务，不涉空间参照
- 图像描述生成（"描述这张图片"）—— 语言生成任务，空间精度要求低
- 简单 OCR —— 文字提取不依赖空间推理

**应对策略**：根据任务类型选择模型。空间推理任务用 DeepSeek 识图模式，纯感知/描述任务用竞品可能更稳。

### 陷阱 3：App 端与网页端行为不一致

IT之家实测发现，App 端识图模式仍显示"图片理解功能内测中"提示，而网页端无此提示。**实战影响**：

- App 端可能是灰度发布或功能不完整版本
- 如果你在开发基于 DeepSeek 多模态 API 的应用，需要确认 App 端和 API 端使用的是同一模型版本

**应对策略**：生产环境依赖 API 端，不要以 App 端表现为准。关注 DeepSeek API 文档的版本更新。

## 实用评估

### 什么场景值得用

- **空间推理任务**: 需要精确描述图像中物体位置关系的场景（"左上角第三个"、"右边的两个之间"），视觉原语框架在此类任务上有理论优势
- **复杂计数**: 技术报告特别提到计数 benchmark，适合需要精确计数的图像分析
- **视觉问答（VQA）**: 需要结合图像内容和空间位置回答的问题
- **UI 截图分析**: Agent 分析 UI 布局、定位元素位置、对比设计稿与实现
- **低成本多模态需求**: 紧凑模型架构意味着更低的推理成本，适合大规模部署

### 什么场景不值得用

- **超高分辨率图像分析**: 低图像标记预算策略可能导致细节丢失，如果任务需要极高的图像细节分辨率，可能不如专门的高分辨率 MLLM
- **纯文本任务**: 如果不需要图像理解能力，DeepSeek 的纯文本模型（V3.2-Exp 等）在成本和性能上可能更优
- **实时视频理解**: 当前上线的是静态图像模式，视频理解能力未提及
- **非空间类的简单图像任务**: 图像分类、简单 OCR 等任务，视觉原语框架无额外优势

### 迁移成本

- **从其他 MLLM 迁移**: 如果已有基于 GPT-5/Claude 多模态 API 的集成，迁移到 DeepSeek 多模态 API 主要涉及 API 适配层改造。需确认 DeepSeek 多模态 API 的接口格式（TODO: 待确认具体 API 格式和定价）
- **从 DeepSeek-VL2 本地部署升级到 API 端**: 如果你之前使用开源 VL2 模型本地部署，迁移到 API 端可以免去 GPU 成本，但需评估 API 调用成本 vs 本地推理成本
