### 实战陷阱与建议

**陷阱 1：过度依赖自动化迁移**
- 问题：Claude Code 可以转换语法，但无法理解业务上下文
- 建议：关键业务逻辑必须人工审查，特别是金融、医疗等监管行业

**陷阱 2：忽视测试债务**
- 问题：老代码往往测试覆盖率低，迁移后难以验证正确性
- 建议：先用 Claude Code 生成 characterization tests，再开始迁移

**陷阱 3：低估数据迁移复杂度**
- 问题：代码迁移容易，但数据库 schema 变更、数据格式转换容易出错
- 建议：将数据迁移作为独立工作流，用 Claude Code 生成迁移脚本 + 回滚脚本

**陷阱 4：团队技能断层**
- 问题：迁移后的代码使用新范式，原团队可能不熟悉
- 建议：在迁移过程中安排知识转移，用 Claude Code 生成文档和培训材料
