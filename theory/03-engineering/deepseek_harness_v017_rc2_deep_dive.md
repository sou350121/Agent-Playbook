## 是什么 / 解决什么问题

DeepSeek Harness（`dsh`）是深度求索于 **2026 年 8 月开源**的一款智能体运行时（Agent Harness）。在此之前，它的标准用法是两条：跑一个 WebUI，或者在终端里执行 `npx @deepseek-ai/dsh`。这两条路对工程师够用，但对更广泛的用户（尤其是只想「装一个应用、打开来用」的人）来说，门槛都卡在环境准备上：装 Node.js、开终端、记命令。

## 技术架构拆解

### 核心设计决策

- **Electron 壳 + 复用现有 Web UI**：据 ReadHub 转述，桌面端基于 Electron 开发，**直接复用现有 Web UI 及各类运行逻辑**，而非重写一套原生界面。这是一个典型的「低边际成本换覆盖面」决策——已有 Web 资产几乎零改动就获得原生窗口、开机即用、系统级集成。
- **免 Node.js 运行时**：把 Node 依赖随应用一起打包分发，用户不需要自己准备环境。牺牲的是安装包体积，换来的是「下载即可用」。
- **「一切皆插件」架构**：候选信号显示 dsh 底层基于 **Cordis** 插件体系（候选摘要记为「基于 Cordis『一切皆插件』」）。这意味着**模式、工具、甚至界面本身都可以由插件组合而来**——「创造模式」让 Agent 写插件来定制 DSH，正是这套架构的产品化出口。
- **双节「逢假必更」的发布节奏**：ReadHub 指出 DeepSeek 延续了「逢假必更」的惯例，**Mac / Windows 版本已在社区传开，均通过官方公证，内置版本更新功能**。也就是说分发链已具备自动更新能力，但官方渠道口径仍克制。
- **实名认证 + 自带 API Key**：客户端**非纯免费，需实名认证，支持用户自行接入 API 密钥**。这既是合规选择，也说明 dsh 定位是「客户端 + 你的模型额度」，而不是「DeepSeek 全托管」。
- **执行可控性前置**：功能覆盖里包含**网页搜索配置、智能体团队、本地化执行管控**——「本地化执行管控」尤其关键，即本地 Agent 跑终端/文件操作时的权限与范围约束。

## 实用评估

### 什么场景值得用

- **零配置体验 Agent Harness**：不装 Node、不开终端，下载桌面应用就能跑一个完整 Agent。对评测「Agent 到底能干什么」的人，这是最低摩擦的入口。
- **批量数据整理（PTC 模式）**：源材料明确 PTC「包含标准模式的所有能力，更适合批量调用工具，并对结果进行筛选、整理、去重、统计或汇总」——这是把 Agent 当「可编排脚本」用的场景，桌面壳不影响吞吐，反而让监控更方便。
- **基线对比（极简模式）**：极简模式「Agent 仅使用终端工具完成任务，适合测试和对比其基础表现」，适合做消融——关掉花哨工具后看纯执行能力。
- **对话式定制（创造模式）**：能「让 Agent 编写插件，添加新功能或界面；也能组合工具和提示词，创建自己的模式」，是插件架构的产品化出口，适合想低成本扩展 Agent 行为的人。
- **本地执行有管控诉求**：功能覆盖含「本地化执行管控」，对在意 Agent 操作本地机器边界的用户是加分项。

### 什么场景不值得用

- **生产依赖**：`V0.1.7-rc.2` 是 rc 预览，**官方尚未正式发布**，稳定性与兼容性存在限制；把它当作生产 Runtime 的底座风险高。
- **headless / CI 集成**：桌面 GUI 与自动化管线方向相悖。要在 CI 或服务端无人值守跑 dsh，仍应回到命令行/WebUI 路线。
- **要求完全免费**：桌面客户端**非纯免费，需实名认证**，虽支持自带 API Key，但「免费白嫖」预期会落空。
- **非 Windows/macOS 平台**：目前仅 Windows x64 与 macOS Apple Silicon，Linux / Intel Mac 用户暂不在覆盖内。
- **英文/国际化场景**：源材料全为中文媒体报道，国际化支持情况 `> TODO: 未说明`。
