## 是什么 / 解决什么问题

我们每天的工作分散在浏览器、桌面应用、终端和通讯工具中 — 每个都有自己的界面和习惯，彼此割裂。现有的自动化工具要么需要写代码（AppleScript、Python），要么是僵化的宏录制器（坐标依赖，UI 一变就失效），要么只能操作单一应用。

Understudy 试图解决这个问题：它是一个**可教学的桌面代理**，像人类同事一样操作你的电脑 — GUI、浏览器、Shell、文件系统全部整合在一个本地运行时中。你向它演示一次任务，它提取**意图**（而非坐标），记住成功路径，随时间发现更快的执行路线，最终独立处理例行工作。

关键设计哲学：**无需 API 集成，无需工作流构建器**。你只需演示一次。

这个名字来自戏剧术语 — "understudy"（替补演员）观看主角表演，学习角色，在需要时接替。Understudy 的设计正是模仿这个学习过程。

## 技术架构拆解

### 核心设计决策

Understudy 的核心是一个**五层渐进架构**，每一层都依赖下一层，形成从"能做"到"主动做"的完整路径：

```
Layer 1: 原生 GUI 能力 → 像人一样操作软件
         ↓
Layer 2: 从演示中学习 → 观看一次，学习，验证，纠正
         ↓
Layer 3: 记住成功路径 → 减少随机性和重复学习
         ↓
Layer 4: 随时间变快 → 从 GUI 升级到更优执行路线
         ↓
Layer 5: 主动自主性 → 在不打扰用户的情况下注意并行动
```

当前状态：
- **Layer 1-2**: 已实现，今日可用
- **Layer 3-4**: 部分实现
- **Layer 5**: 长期方向

这个分层设计的关键在于：**系统通过实际使用"赚取"向上晋升的资格**，没有捷径。每次成功执行都积累证据，推动系统向更高层进化。

### 执行路线统一调度

Understudy 不是单纯的 GUI 点击器。它是一个统一的桌面运行时，在一次代理循环、一次会话、一个策略管道中混合使用电脑提供的每种执行路线：

| 路线 | 实现 | 覆盖范围 |
|------|------|----------|
| GUI | 13 个工具 + 截图定位 + 原生输入 | 任何 macOS 桌面应用 |
| Browser | Playwright 托管 + Chrome 扩展中继 | 任何网站，含登录会话 |
| Shell | bash 工具，完整本地访问 | CLI 工具、脚本、文件系统 |
| Web | web_search + web_fetch | 实时信息检索 |
| Memory | 跨会话语义记忆 | 持久化上下文和偏好 |
| Messaging | 8 个频道适配器 | Telegram、Slack、Discord、WhatsApp、Signal、LINE、iMessage、Web |
| Scheduling | Cron + 单次定时器 | 自动化重复任务 |
| Subagents | 子会话并行工作 | 复杂多步委托 |

规划器为每个步骤决定使用哪条路线。单个任务可能浏览网站、运行 Shell 命令、点击本地应用、发送消息 — 全部在一个会话中完成。

### GUI 定位：双模型架构

这是 Understudy 最有趣的技术决策之一。**主模型决定做什么，独立的定位模型决定在屏幕哪里做**。这种分离意味着：
- 规划模型不需要像素级坐标预测能力
- 定位模型不需要任务上下文

定位流程：
```
主模型："点击提交按钮"
  → 截图（窗口模式或显示模式）
  → HiDPI 归一化（Retina 物理像素 → 逻辑像素）+ 自适应缩放
  → 定位模型预测：边界框 + 点击点 + 置信度
  → 坐标映射（模型空间 → 原始图像空间）
  → 点击点稳定化（小控件边缘偏差 >22% 校正到中心）
  → [小目标 ≤160px] 裁剪放大进行精修
  → [复杂模式] 生成模拟覆盖层 → 验证模型确认
  → 被拒 → 生成标记失败位置的引导图 → 重试（最多 3 轮）
  → 坐标转换到显示空间 → CGEvent 原生执行
  → 执行后截图 → 验证结果
```

三个坐标空间：物理像素（原始截图 PNG 尺寸）→ 逻辑点（macOS 显示坐标，CGEvent 期望的）→ 模型像素（发送给定位模型的缩放版本）。scaleX/Y 桥接物理到逻辑，modelToOriginalScale 桥接模型到物理。

定位基准测试：**30/30 目标解析** — 包括明确标签、模糊目标、仅图标元素、模糊提示。

### 从演示中学习（Layer 2）

这不是宏录制器。Understudy 学习**任务形状的技能**，而非随机点击列表：

- **原子技能**: 单一能力（点击、滚动、输入、调用 API、发送消息）
- **任务技能**: 由原子技能、路线选择和验证组成的完整任务
- **教学草稿**: 可编辑的任务技能草稿表单
- **已发布任务技能**: 提升为可复用的工作区技能

教学流程：
```
/teach start
  → 双轨录制启动（屏幕视频 + 语义事件）
  → 用户用鼠标键盘执行一次完整任务

/teach stop "提交每周费用报告"
  → SIGINT 停止录制 → 输出 .mov + events.json
  → 证据包构建 → AI 分析 → 教学草稿
  → 进入澄清对话（多轮自然语言交互，完善任务卡）

/teach confirm [--validate]
  → 检查遗留问题 → 锁定任务卡；--validate 触发回放验证

/teach validate
  → 将学到的任务作为实际代理提示回放
  → 分析执行轨迹：区分阻塞性失败和可恢复失败

/teach publish <draftId> [skill-name]
  → 生成 SKILL.md → 热加载到活跃会话
```

发布的 SKILL.md 是三层抽象：
1. **意图过程**（自然语言步骤）
2. **路线选项**（首选/备用路径）
3. **GUI 回放提示**（最后手段，每次从当前截图重新定位）

这意味着：UI 重新设计、窗口调整大小、甚至切换到类似应用 — 只要语义目标仍然存在，技能就能工作。

## 实用评估

### 什么场景值得用

1. **跨应用数据搬运**: 从网页复制数据到本地应用，再整理到表格 — 传统需要写脚本或手动操作，Understudy 可以演示一次后自动执行

2. **定期报告生成**: 每周从多个来源收集数据、整理格式、发送邮件 — 教学一次，之后一键执行

3. **非程序员的自动化需求**: 市场、运营、财务人员需要自动化但不会写代码 — 演示即可

4. **UI 频繁变化的应用**: 传统宏录制器在 UI 更新后失效，Understudy 的语义定位可以适应

5. **混合工作流**: 需要同时操作浏览器、本地应用和终端的任务 — 统一运行时避免切换工具

### 什么场景不值得用

1. **纯 API 可完成的任务**: 如果目标应用有稳定 API，直接调用 API 更可靠、更快

2. **对执行速度要求极高**: GUI 操作天然比 API 慢，定位模型调用也有延迟

3. **Windows/Linux 用户**: 目前仅支持 macOS（依赖 Accessibility API 和 CGEvent）

4. **极度简单的任务**: 如果只是"每天打开某个网站"，浏览器书签或简单脚本更轻量

5. **隐私敏感环境**: 虽然本地优先，但 GUI 定位可能发送截图到模型提供商 — 需要评估合规性

### 迁移成本

从其他工具迁移到 Understudy：

| 来源 | 迁移工作 | 预计工作量 |
|------|----------|------------|
| 宏录制器（Keyboard Maestro 等） | 重新演示任务，生成 SKILL.md | 每任务 5-15 分钟 |
| AppleScript/Python 脚本 | 理解现有逻辑，用自然语言重写任务卡 | 每任务 10-30 分钟 |
| 手动操作 | 直接演示一次 | 任务本身耗时 + 5 分钟教学 |
| Zapier/Make 等云自动化 | 仅适用于纯 API 任务；GUI 任务无法迁移 | 不适用 |

Understudy 的优势在于：**迁移是一次性的**。一旦技能发布，UI 变化不需要重新录制（除非语义目标消失）。

## 对你的意义

如果你正在构建 Agent 系统或研究桌面自动化，Understudy 有几个值得关注的设计模式：

1. **五层渐进架构**: 这是一个通用的 Agent 成熟度模型。你的 Agent 是否也有类似的"学习→记忆→优化→主动"路径？

2. **双模型定位**: 将"做什么"和"在哪里做"分离，降低了主模型的认知负担。这个模式可以应用到其他 GUI 操作场景。

3. **SKILL.md  artifact 格式**: 三层抽象（意图/路线/提示）是一个很好的知识表示设计。它平衡了可读性（自然语言）和可执行性（路线选项）。

4. **证据包构建**: 录制时同时捕获视频和语义事件（Accessibility API 查询），为后续 AI 分析提供丰富上下文。这个设计比单纯录屏更有信息量。

**建议**: 如果你是 macOS 用户且有重复性桌面工作，值得花一个下午试用。从一个小任务开始（如"每天从 X 网站复制数据到 Y 表格"），走完整教学流程，观察生成技能的质量。

如果你是非 macOS 用户或主要做 API 集成，可以关注其设计思想，但实际使用价值有限。
