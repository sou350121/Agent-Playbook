## 是什么 / 解决什么问题

大模型的安全防护长期面临一个经济学困境：效果好的检测器太贵。Anthropic 2025 年推出的第一代 Constitutional Classifiers 在推理成本上增加了 23.7%；OpenAI 也对外提过，某些发布中安全推理占到算力开销的 16%（来源：AlphaSignal 转述官方细节）。于是大多数平台的折中方案是——只对可疑流量采样、或者只检测输入端。

Self-Assessment 的思路反过来：既然模型本来就要把整段对话读一遍才能回答，那就别另起一套分类器，而是让同一个模型在回答之后「补一句判断」。

机制上是典型的 suffix 注入：Claude 正常回答后，系统在上下文末尾附加一条隐藏指令，要求模型输出一个简短内部判定，字段包括：是否涉及潜在有害请求、属于哪类危害、人工审核优先级分数、Claude 是否拒绝过、以及一句解释成因的自由文本。无害对话只输出 `{"flagged": false}`。

这套东西从 2026 年 6 月起就在生产环境跨 Claude 模型（含 Fable 5）静默运行，10 月底才公开技术细节。也就是说，它已经积累了两个多月的真实误用数据——这部分比 benchmark 更值得看。

## 技术架构拆解

### 核心设计决策

- **复用 KV cache，而不是重新过一遍对话**：回答生成后，整段对话的 key-value 缓存仍在，评估只需挂上去算那 10 来个 token。这是成本从 23.7% 掉到 <2% 的根本原因——不是把分类器变小了，而是根本不重算。
- **用模型自身判断，而不是固定规则表**：因此能识别训练时未编目的行为模式。测试中把某类危害样本从训练数据里整类删掉，仍能识别约 90%。
- **冻结回答、只训练判定 token**：SFT 阶段只在 assessment token 上计算 loss，避免奖励模型继续生成有害内容。
- **两阶段训练（SFT + RL）**：RL 用 6 个可验证奖励——JSON 合法、flagged 标签一致、类别精确匹配、子策略精确匹配、拒绝判定一致、优先级分数接近 teacher。全部可程序化校验，无需人工标注。
- **合成数据管线**：每个 subpolicy 生成 32 个主题 × 32 个场景 = 1024 个有害 + 1024 个良性场景，良性样本刻意与有害样本同主题，构成 hard negatives。
- **teacher 是带完整内部策略文档上下文的 prompted classifier**（基于 Claude Mythos Preview），也就是说，评估能力的上限锚定在「带着政策手册答题的强模型」上。
- **只记录不拦截**：官方明确它不用于实时阻断，而是喂给后续离线审核与执法流程。

### 生产侧发现（6 月至今）

- 8 月单月，仅凭 self-assessment 针对一个 API 客户产出超过 100,000 条儿童性虐待与剥削材料相关标记，Anthropic 已上报 NCMEC。
- 约三分之一的标记落在既有危害分类体系之外；聚类后主要是三件事：非法蒸馏 Claude 的推理过程、prompt injection 攻击、以及 agent 执行用户未授权的动作。
- 超过一半被识别出的组织，在上个月没有触发任何其他检测源；其中一例是用 Claude Code 搭建的自动化杀猪盘（romance scam）操作。
- 可插入 session 级 policy block，让已核实的安全团队在指定软件上做测试而不被当作入侵。

### 什么场景值得用

- **Agent 平台方**：第三条发现尤其关键——「agent 执行用户未授权的动作」是被自评抓出来的高频类别。做 agent builder 的团队应该把这当作 agent 侧审计信号，而不只是模型安全信号。
- **多租户 API / 开放平台**：<2% 的开销意味着可以默认全开，而不是采样。合规可追溯的成本结构发生了变化。
- **需要长尾风险发现**：固定分类器永远追不上新模式，自评的泛化性（整类删除后仍 90%）是这里最实用的卖点。

### 什么场景不值得用

- **把它当唯一防护**：54% 攻击成功率。官方自己说得很清楚，对抗性阻断仍需独立分类器（25%）。
- **需要确定性、可审计的规则**：模型判定带来解释性，但带不来「同一输入必然同一输出」的合规确定性。
- **对隐私极度敏感的场景**：判定是后台生成的，虽然不打断用户，但 verdict 会被发送/eval 用于审核。面向终端 C 端的产品需要明确的数据政策面。
- **小模型部署**：1% FPR 下召回从 ~16% 到 ~96% 的跨度说明，这个能力高度绑定基座规模，小模型上不成立。

### 迁移成本

若你要在自建系统里复刻这个形态，大致需要：
1. 拿到回答后的 KV cache 句柄（vLLM / SGLang 需确认是否支持在生成后再续一次短续写且命中前缀缓存）；
2. 定义 verdict schema，并用 teacher 模型批量标注合成语料；
3. SFT 只在 verdict token 上算 loss（loss masking）；
4. RL 侧 6 个可验证奖励——这部分是工程量最大的，尤其「优先级分数接近 teacher」需要一个连续值 reward（用负绝对误差即可）。
估算是小团队 2-4 周可做出 POC，但达到官方那种 1% FPR 召回水平，数据管线的投入更大。

## 对你的意义

两条线各有落点：

- **AI App / Agent 工程线**：「三分之一标记在既有分类之外，其中最高频的是 agent 越权动作」——这条对你正在搭的 agent UI / workflow 安全层是直接输入。如果你在做 agent builder，审计信号不该只来自 API gateway 日志，模型层的 verdict 是一个更便宜的第二信号源。
- **VLA / 具身线**：同样的「生成后自评」形态对 VLA 后训练有借鉴价值——策略输出动作后，让同一模型缓存给出「该动作是否异常 / 是否需要人工接管」的判定。相比独立 safety critic，复用 KV cache 的开销优势在实时控制回路里意义更大。**但目前没有 VLA 侧的公开实现，属于推测。**

具体建议：**观望但要读细节**。这不是一个能直接拿来用的产品功能（除了 Claude 平台本身），而是一份工程上非常干净的「低成本监控」参考架构。如果你是做 agent 平台的，建议现在就去读官方页面的 RL reward 设计部分。

## 关键代码/配置片段

官方公开的判定输出契约（据 AlphaSignal 对官方细节的转述）：

```json
{"flagged": false}
```

有害场景下扩展为：

```json
{
  "flagged": true,
  "category": "...",
  "subpolicy": "...",
  "priority": 0.0,
  "refused": true,
  "explanation": "一句话说明判定成因"
}
```

风险分数由模型对 `true` 这个 token 赋予的概率连续导出——这是一个很实用的小技巧：不额外训练回归头，直接从 logprob 拿分数。
