## 是什么 / 解决什么问题

2026 年 7 月 3 日，阿里巴巴内部宣布全面禁用 Anthropic 旗下 Claude 全线产品，涵盖 Sonnet、Opus、Fable 等多个模型以及 Claude Code 在内的 Agent 产品，7 月 10 日正式生效。所有员工被要求卸载 Anthropic 旗下产品。

这一"反向禁用"的背景是：自 2026 年初起，阿里内部为鼓励员工使用 AI 技术，不仅推出内部模型免费额度，还对外部模型实行大额报销政策。员工可自由选择 Claude、GPT、Gemini 等外部模型，不少程序员每周消耗额度高达数百美元。Claude Code、OpenAI Codex 与阿里旗下 Qoder 都被列为高频使用的 Agent 工具。

触发事件是 Reddit 用户 LegitMichel777 对 Claude Code 2.1.196 版本的逆向分析发现：自 2026 年 4 月 2 日发布的 2.1.91 版本起，Claude Code 内置了一套隐蔽的检测机制。该机制在用户开启智能体时，检查系统时区是否为中国时区（Asia/Shanghai 或 Asia/Urumqi），并匹配一份包含 **147 个条目**的域名清单——涵盖百度、阿里巴巴、字节跳动、月之暗面、MiniMax、阶跃星辰等中国科技企业及 AI 实验室的域名，以及大量 Claude API 中转服务地址。

更关键的是，检测结果的传输方式极为隐蔽：Claude Code **并未通过独立的遥测字段上报数据**，而是将信息直接编码在每次请求都会发送的系统提示词中。例如，系统时区为中国时区时，日期格式会从 "2026-06-30" 变为 "2026/06/30"。这种编码方式意味着即使用户审查网络请求，也难以察觉异常。

Anthropic 团队成员 Thariq Shihipar 在 X 上回应称，该机制是 2026 年 3 月上线的"实验性"措施，目的是防止未经授权的账户转售以及防范模型蒸馏攻击。他表示团队此后已部署了更强的缓解措施，相关 PR 已合并，2026 年 7 月 2 日发布的新版本中已"完全回滚"并删除相关检测代码。

## 技术架构拆解

### 核心设计决策分析

**1. 隐蔽检测机制的技术实现**

Claude Code 的检测机制有三个关键设计特征，使其极难被普通用户察觉：

- **时区检测**: 检查系统时区是否为 Asia/Shanghai 或 Asia/Urumqi——这是最基础的地理围栏
- **域名清单匹配**: 147 个条目覆盖了几乎所有中国头部 AI 企业和实验室，以及 Claude API 中转服务——这表明检测目标明确指向"中国实体"和"灰色渠道"
- **系统提示词编码**: 这是最隐蔽的一环。不通过独立遥测通道，而是将检测结果编码在每次请求都有的系统提示词中（如日期格式变化）。这意味着：
  - 即使用户抓包审查网络请求，看到的也是"正常"的 API 调用
  - 检测数据与正常业务数据混在一起，无法通过流量分析分离
  - 只有逆向分析系统提示词的生成逻辑才能发现

**2. Anthropic 的设计动机**

从 Anthropic 的回应来看，设计动机有两个：
- **防止账户转售**: 通过识别中国企业/域名，阻止中国用户通过中转 API 使用 Claude
- **防止模型蒸馏**: 阻止中国 AI 实验室通过大量 API 调用蒸馏 Claude 的能力

这两个动机本身是合理的商业/安全考量，但**实现方式的选择**——隐蔽编码在系统提示词中——引发了严重的信任问题。
