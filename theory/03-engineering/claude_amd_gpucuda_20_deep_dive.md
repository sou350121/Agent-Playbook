### 背景：CUDA 护城河的本质

CUDA 从 2006 年发布至今，积累了近 20 年的生态壁垒。这个壁垒不仅仅是编译器、数学库（cuBLAS、cuDNN）、调试器（Nsight）、性能分析工具（Nsight Systems）这些可见的软件层——更深层的是**一代代 GPU 工程师的手感**。

## 技术架构拆解

### 核心设计决策

AMD 的做法不是"让 Claude 自己去摸索 ROCm"，而是**系统性地为 Agent 可用性重构了工具链**：

#### 1. ROCm.AI — Agent 专用的 GPU 工具箱

ROCm.AI 是 AMD 在 Advancing AI 2026 大会上发布的新产品层，专门面向 Claude、Codex、Cursor 等 AI Agent 设计。它不是一个 API，而是一套完整的工具链：

| 组件 | 功能 | 传统对应物 |
|------|------|-----------|
| AMD Skills | 经过验证的 ROCm 知识库，Agent 的"起点经验" | 文档 + Stack Overflow |
| ROCm CLI | Agent 可调用的真实机器接口 | 命令行工具 |
| 环境部署模块 | Agent 自动安装依赖、配置环境 | 手动 setup |
| 日志/故障诊断 | Agent 自主读取日志、定位问题 | 人工 debug |

关键设计哲学：**Agent 不需要"学习"ROCm——它直接拿到经过验证的知识，然后自己执行。**

#### 2. AI-Readable ISA — 芯片说明书的重写

AMD AI 软件与解决方案副总裁 Anush Elangovan 透露：**每一代 AMD GPU 都会公开指令集，并提供 AI 可读的 ISA（Instruction Set Architecture）文档。**

这意味着：
- 传统做法：工程师读芯片手册 → 理解指令集 → 编写优化内核
- 新做法：Agent 读 AI-Readable ISA → 直接上手调性能

AMD 甚至改变了芯片说明书的写法——不是为人类工程师写的，而是为 AI Agent 写的。这是一个范式级别的转变。

#### 3. Hyperloom — 自动化性能优化引擎

Hyperloom 是 AMD 用于自动性能优化的核心引擎：

```
┌─────────────────────────────────────────────────┐
│                  Hyperloom                       │
│                                                  │
│  1. 拉起推理服务 → 跑出基线性能                   │
│  2. 分析 CPU/GPU 瓶颈 → 定位性能卡点              │
│  3. 测试不同配置 → 搜索最优参数空间               │
│  4. 生成定制内核 → 针对具体模型优化               │
│  5. 重新跑验证 → 确认性能提升                     │
│  6. 沉淀经验 → 下次直接复用                       │
└─────────────────────────────────────────────────┘
```

现场演示数据：
- **MiniMax M3 输出速度提升 38%**（Hyperloom 自动优化后）
- **一次性跑了 14,000 个模型**，测试结果沉淀为可复用经验
