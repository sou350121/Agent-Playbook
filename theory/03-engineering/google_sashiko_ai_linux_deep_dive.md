## 是什么 / 解决什么问题

Linux 内核是世界上最复杂的开源项目之一，每月有数千个补丁提交到 Linux 内核邮件列表（LKML）。代码审查是保证内核质量的关键环节，但人类审查员面临几个根本性挑战：

1. **审查疲劳**：高频提交导致审查员难以保持专注
2. **专业知识分散**：不同子系统需要不同领域的专家（内存管理、并发、安全、硬件驱动等）
3. **隐性 bug 难以发现**：use-after-free、竞态条件、RCU 违规等问题需要深度追踪执行流
4. **审查覆盖率不足**：大量补丁因缺乏审查员而延迟合并

Sashiko 的定位不是替代人类审查员，而是作为**自动化第一道防线**，在人类审查之前筛选出明显问题，并提示人类审查员关注高风险区域。

项目名称 "Sashiko"（刺し子）源自日本传统的装饰性加固缝纫技术——通过密集的小针脚来修补或强化磨损部位。这隐喻了项目的使命：通过自动化、智能化的补丁审查来强化 Linux 内核。

## 实用评估

### 什么场景值得用

1. **内核贡献者提交前自查**
   - 在发送补丁到 LKML 之前先用 Sashiko 跑一遍，可以提前发现约 50% 的潜在问题
   - 减少被审查员打回的概率，加速合并流程

2. **下游内核维护者**
   - 如果你维护发行版内核或企业定制内核，Sashiko 可以帮助审查 backport 补丁
   - 特别是安全修复补丁，Stage 6 的安全审计很有价值

3. **内核学习者**
   - Sashiko 的审查报告展示了专业审查员的思考路径
   - 9 个阶段本身就是内核代码审查的检查清单

4. **研究 Agentic AI 工程实践**
   - Sashiko 是目前最成熟的垂直领域 Agentic AI 应用之一
   - 其多阶段协议、误报过滤、LLM 后端抽象等设计值得参考

### 什么场景不值得用

1. **非内核项目**
   - Sashiko 的 prompt 和审查逻辑高度针对内核，用于其他项目效果会大幅下降

2. **代码隐私敏感场景**
   - Sashiko 需要将补丁和相关内核代码发送给 LLM 提供商
   - 虽然可以本地部署，但 token 成本需自行承担

3. **预算有限的个人开发者**
   - 审查复杂补丁可能消耗数十万 token
   - Gemini 3.1 Pro 和 Claude 的 API 成本不低（尽管 Google 为公共服务买单）

4. **期望 100% 准确率**
   - Sashiko 仍有约 20% 误报率
   - 输出是概率性的，相同输入可能产生不同结果

### 迁移成本

如果你已经在用其他审查工具：

| 从 X 迁移到 Sashiko | 工作量 | 说明 |
|-------------------|-------|------|
| 纯人工审查 | 低 | 只需注册 sashiko.dev 或本地部署 |
| Coccinelle/Sparse | 中 | Sashiko 补充而非替代，可并行使用 |
| GitHub Copilot | 低 | Sashiko 专注审查，Copilot 专注生成，定位不同 |

本地部署步骤（摘自官方文档）：

```bash

git clone --recursive https://github.com/rgushchin/sashiko.git

# 2. 配置 Settings.toml
# 设置 LLM 提供商、模型、数据库路径等
```

### Settings.toml 配置示例（Gemini）

```toml
[ai]
provider = "gemini"

path = "sashiko.db"

[server]

port = 8080

[git]
kernel_path = "/path/to/linux"

[review]
concurrency = 4
worktree_count = 2
```

### Claude 配置（支持 prompt caching）

```toml
[ai]
provider = "claude"
model = "claude-sonnet-4-6"
max_input_tokens = 950000

[ai.claude]
prompt_caching = true
```

### CLI 使用示例

```bash
# 审查本地 git 仓库中的补丁
sashiko-cli review --repo /path/to/linux --commit abc123

# 查看审查历史
sashiko-cli history

# 导出审查报告
sashiko-cli export --patch-id 12345 --format email
```
