## 技术架构拆解

### 核心设计决策

**1. 雙層訪問控制架構**

OpenAI 設計了兩層訪問機制：

| 層級 | 訪問方式 | 適用對象 | 摩擦程度 |
|------|---------|---------|---------|
| 基礎層 | 所有用戶默認訪問 | 一般用戶 | 標準安全限制 |
| 可信層 | ID 驗證 + TAC 標記 | 驗證通過的防御者 | 降低摩擦 |

關鍵設計理念：**不依賴中心化決策來判斷「誰有資格防御」**，而是用客觀標準（身份驗證）和自動化流程來擴大訪問範圍。

**2. 專用模型變體（GPT-5.4-Cyber）**

GPT-5.4-Cyber 被標記為「cyber-permissive」（網絡寬鬆）模型，意味著：
- 在防御性網絡安全任務上減少拒絕率
- 保留對明顯惡意請求（憑證竊取、惡意軟件創建）的拒絕能力
- 基於 GPT-5.4 微調，而非從頭訓練

**3. 漸進式部署策略**

OpenAI 明確表示這是「迭代部署」策略的一部分：
```
GPT-5.2 → 引入網絡安全特定安全訓練
    ↓
GPT-5.3-Codex → 擴展安全防護 + 分類器監控
    ↓
GPT-5.4 → 分類為「高」網絡能力 + TAC 試點
    ↓
GPT-5.4-Cyber → 專用防御模型 + 大規模 TAC 擴展
```

**4. 三原則指導框架**

- **民主化訪問**：用清晰的客觀標準（如 KYC、身份驗證）取代任意性決策
- **迭代部署**：將系統謹慎投入實際使用，根據反饋持續改進
- **投資生態系統韌性**：通過贈款、開源貢獻、技術工具（如 Codex Security）支持防御者社區

### 什么场景值得用

**1. 開源項目維護者**

**2. 企業安全團隊**
- 企業可通過 OpenAI 代表為整個團隊申請默認可信訪問
- 適合需要大規模代碼審計、自動化漏洞檢測的場景
- $10M API 積分贈款可降低試點成本

**3. 獨立安全研究人員**
- 自助 ID 驗證流程相對簡單（相比邀請制）
- 適合負責任的漏洞披露流程
- 可訪問 GPT-5.4-Cyber 的降低摩擦能力

**4. 關鍵基礎設施保護團隊**
- OpenAI 明確將此類團隊列為優先服務對象
- 可申請更高級別的訪問權限
- 符合「生態系統韌性」投資原則

### 什么场景不值得用

**1. 未經授權的滲透測試**
- TAC 明確禁止「未經授權的測試」
- 即使通過 ID 驗證，此類請求仍可能被拒絕
- 需通過額外的 Google Form 申請特殊訪問

**2. 紅隊演練（無客戶授權證明）**
- 需要提供客戶授權證明才能獲得相應訪問權限
- 純學術研究可能無法滿足要求

**3. 非防御性用途**
- 數據竊取、惡意軟件創建、破壞性測試均被禁止
- 分類器監控會檢測可疑活動信號

**4. 不願提供身份證明的用戶**
- TAC 強制要求政府 ID 驗證
- 隱私敏感用戶可能不適合此方案

### 迁移成本

**從標準 OpenAI API 遷移到 TAC：**
- 時間成本：ID 驗證約 5-15 分鐘（取決於 Persona 處理速度）
- 技術成本：無需代碼變更，僅需在訪問時攜帶 TAC 標記
- 合規成本：需同意額外的使用條款和監控條款

**從 Anthropic Glasswing 遷移到 OpenAI TAC：**
- 訪問機制差異：Glasswing 是邀請制，TAC 是自助驗證
- 若已通過 Glasswing 審批，遷移動力較低（除非需要 GPT-5.4-Cyber 特定能力）
- API 接口差異：需調整調用方式（OpenAI vs Anthropic SDK）
