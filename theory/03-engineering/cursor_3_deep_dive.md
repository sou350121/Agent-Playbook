## 是什么 / 解决什么问题

Cursor 3 的发布标志着 AI 编程工具从「第二时代」（同步提示 - 响应循环）正式迈入「第三时代」（多智能体自主协作）。在旧模式下，开发者需要手动管理多个智能体会话、在终端/工具/窗口间切换、并持续 micromanage 每个智能体的进度。Cursor 3 通过统一工作区界面解决了这些问题。

核心变化有三层：
1. **界面重构**：从 VS Code fork 的编辑器界面升级为以智能体为中心的多工作区布局
2. **执行模型扩展**：本地智能体与云端智能体无缝切换，支持长周期任务离线运行
3. **协作抽象提升**：智能体产出从「代码 diff」升级为「可验证的 artifacts」（演示、截图、录屏）

这次更新不是功能叠加，而是交互范式的根本转变——开发者角色从「逐行指导」变为「定义问题 + 设定验收标准 + 审查产出」。

## 技术架构拆解

### 核心设计决策

| 决策 | 理由 | 权衡 |
|------|------|------|
| 保留 IDE 内核（LSP、调试器） | 智能体仍需要人类深度介入审查和修改 | 界面复杂度增加，学习曲线陡峭 |
| 云端智能体独立 VM 运行 | 避免本地资源竞争，支持离线持续运行 | 需要处理本地/云端状态同步 |
| Artifacts 优先于 diffs | 视频/截图比代码 diff 更易快速验收 | 存储成本增加，需要新的审查习惯 |
| 多仓库原生支持 | 现代项目往往跨多个 repo | 上下文管理复杂度提升 |

## 实用评估

### 什么场景值得用

1. **多仓库微服务项目**：原生多 repo 布局避免频繁切换窗口，智能体可跨仓库协调变更
2. **长周期重构任务**：将任务交给云端智能体后关闭笔记本，任务继续运行并返回 artifacts
3. **团队并行开发**：多个智能体同时处理不同模块，人类开发者专注审查和集成
4. **快速原型迭代**：Composer 2 模型（$0.50/M input）支持高频率试错，成本可控

### 什么场景不值得用

1. **单一小型脚本项目**：多智能体并发优势无法发挥，传统 IDE 更轻量
2. **严格数据合规场景**：云端智能体需要代码上传至 Cursor VM，可能违反某些企业安全政策
3. **预算极度受限**：虽然 Composer 2 定价较低（$0.50/M input），但高频使用仍会产生显著费用
4. **网络不稳定环境**：云端智能体依赖持续网络连接，本地模式功能受限

### 迁移成本

从 Cursor 2 或 VS Code + Copilot 迁移：
- **学习成本**：约 2-4 小时熟悉新界面（Agents Window、Artifacts 审查）
- **配置成本**：需设置云端 VM 权限、配置多仓库访问
- **习惯调整**：从「实时对话」转向「任务委派 + 验收」需要思维转变
- **代码库兼容**：无破坏性变更，现有项目可直接打开
