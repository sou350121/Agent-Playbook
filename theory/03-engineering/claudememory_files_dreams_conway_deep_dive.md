## 是什么 / 解决什么问题

过去一年，AI 助手最大的体验断点之一就是**上下文的一次性**：会话关掉，你辛苦解释的项目背景、团队术语、写作偏好就随之蒸发。你要么每次重新解释，要么把一大段说明塞进 prompt 里。Anthropic 这次发布的记忆更新，正面处理的就是这个断点。

根据 Anthropic 官方博客《Claude's memory works everywhere, and you decide what's in it》（2026-08-25），本轮变化的重点有三层：

1. **chat 与 Claude Cowork 共享同一份记忆**。以前 chat 里的记忆和 Cowork（云端任务执行产品）是割裂的；现在「你在 chat 里建立的上下文，在你把任务交给 Cowork 的那一刻就已经存在」，反之 Cowork 里产生的内容也会回流到 chat。
2. **记忆写入从「会话后摘要」改成「边聊边写」**。官方原话：*"Claude now adds topics to memory as you chat, instead of summarizing conversations after they end."* 也就是说，你随口提到「项目截止日改到九月了」，下一段对话就已经知道，不用再说「记住这个」。
3. **记忆以文件形式对用户完全可见可编辑**。所有被记住的内容都在 Memory 设置里的 **Topics** 下列成一份文件列表，可以逐条读取、编辑、删除。

把这三层合起来看，Anthropic 卖的其实不是一个「记忆功能」，而是一套**用户可治理的持久记忆层（governable persistent memory）**——这在企业场景里是关键：记忆不再是模型肚子里的黑箱，而是一份你能审阅、能修改、能清空的资产。

## 技术架构拆解

### 核心设计决策

Anthropic 在公告里透露了几项明确的设计取舍，每一项目后都有清晰的工程动机：

- **记忆文件化（Topics 列表）**：记忆不是一段不可见的 embedding，而是「一小组短文件」。官方给的例子是：把公司旧名字在一个文件里改正，此后所有对话都会用对的名字。文件化 = 可审阅 + 可定点修正 + 可版本化（天然适合 diff/审计）。
- **边聊边写（incremental write）**：替代「会话结束后总结」。好处是记忆新鲜度高、无需等待总结窗口；代价是**错误的即时污染风险更高**——所以官方同时提供了「随时暂停记忆或重置」的开关。
- **跨端单一记忆（chat ↔ Cowork）**：同一份记忆贯穿 chat 与云端执行的 Cowork。这是把「对话」与「执行」共享同一个身份画像，避免在两个产品里各维护一套用户模型。
- **默认隐私保守**：默认**不**把个人/敏感主题写入记忆——官方明列健康、种族、族裔、宗教信仰、政治、性别认同等。
- **敏感话题可选开启 + 例外黑名单**：用户可打开「include sensitive topics in memory」，开启后每次保存敏感话题都会给出提示，且**不回溯历史**。即便开启，仍有一类内容**永不落库**：SSN / 政府证件号等敏感身份编号、犯罪记录、移民身份、以及任何违反 AUP 的内容；Claude 会在无法更新记忆时告知用户。
- **企业与个人分权**：个人版（Free/Pro/Max）默认开启；Team / Enterprise 由管理员控制组织级可用性，且**在用户主动打开前对个人默认关闭**。

## 实用评估

### 什么场景值得用

- **长期多轮项目**：一个持续数月、涉及多个子任务的项目，背景信息只需解释一次。官方举例直接命中痛点——在 chat 里解释一次「团队如何定义指标」，之后 Cowork 生成的每份季度业务回顾都用同一套定义。
- **跨「对话」与「执行」的连贯工作**：先 brainstorming，再让 Cowork 落地成文档/预算。记忆打通后，Cowork 直接知道负责人是谁、城市、议程和参会人数，无需重述。
- **需要纠错传播的术语/偏好**：把「公司旧名」在一个文件里改掉，全站生效——这对术语、品牌规范、写作风格的统一非常有价值。
- **需要人为治理记忆的团队**：因为记忆是可见文件、且企业有管理开关，比「黑箱记忆」更容易被合规团队接受。

### 什么场景不值得用

- **把它当作精确的个人档案库**：默认不记健康/政治/信仰等敏感话题，且有 SSN、政府证件号、犯罪史、移民身份**永不落库**的硬性限制。需要这类信息的场景，Claude 记忆不是合适载体。
- **对记忆污染零容忍**：边聊边写意味着错误可能被即时吸收，虽然有「逐条编辑 / 暂停 / 重置」，但仍需要用户主动维护，不是「设完即忘」。
- **团队/企业想直接开箱即用**：Team / Enterprise 对个人用户**默认关闭**，必须管理员开放 + 用户自己打开，存在部署摩擦。
- **依赖第三方文档细节做架构决策**：本文中 Dreams / Conway 的机制细节目前缺乏一手来源，若你要基于它们做工程选型，应等官方文档。

### 迁移成本

- **个人用户**：几乎为零。记忆在 Free / Pro / Max 的 web、desktop、mobile 上**默认开启**；移动端更新到最新版本即可。需要留意的是——**敏感话题默认关**，若你要让它记住过敏史这类信息，得手动打开对应设置。
- **企业用户**：需要管理员先在组织级放开可用性，再由用户在设置里开启；这是流程成本，不是技术成本。
- **从「自建记忆方案」迁移**：如果你此前靠外部向量库 / RAG 给助手做长期记忆，Claude 原生记忆提供的是「轻量、可读、可编辑」的基线能力；对精度要求极高的检索场景，短期内更像是**互补**而非**替代**。
