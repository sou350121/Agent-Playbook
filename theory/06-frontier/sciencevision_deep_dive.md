## 是什么 / 解决什么问题

过去一年，多模态模型的 demo 越来越像科幻片：GPT-6 Astra 在 X 上放出的 CAD 生成视频——涡轮增压器每个零件单独建模，能转、能一键拆解展开，视觉上相当漂亮。BenchCAD 上 95.9% 的分数，让评论区直接开始讨论 CAD 工程师的再就业问题。

然后工程师泼了盆冷水：这些零件，一个都别往生产线送。

问题就在这里——「画得像」和「画得对」是两件事。表面上看，模型复刻了 CAD 软件的视觉界面；但从专业工程师的视角，部件之间的几何关系、结构约束、科学原理是否成立，完全是另一个维度。而现有的 3D 理解基准（室内场景、具身交互、抽象结构推理）主要服务日常感知和机器人操作，真正面向科学领域的 3D 理解与推理基准几乎空白，只有医学影像和机械工程等零散专项。

ScienceVision 填的就是这个空白。它由 UniPat AI 和 Elorian AI 构建，出发点是一个问题：**AI 能像科学家一样观察和推理吗？**

评测覆盖 12 个当前最新的开源/闭源前沿模型——GPT-6 Astra、Claude Fable 5.1、Claude Opus 5.5、Gemini 4 Argon、Qwen3.8 Max 等。结果是：没有任何模型能在五个学科同时领先，最高分 0.53（满分 1）。而且 0.53 不是答对率，是含部分得分的平均指标——完全答对的比例还要更低。

## 技术架构拆解

### 核心设计决策

- **题是真三维的**：模型拿到的是分子坐标文件、CT 体数据、机械装配体、建筑模型这样的源数据，不是平面截图。答题必须用领域知识解释三维结构证据，部分题目要先从观察中把目标认出来，再接上拓扑与几何推理。
- **三种证据获取方式，同一套评分**：① 只给原始 3D 数据，模型自己写代码分析；② 数据 + 交互检视工具（旋转、隔离结构、切片、测距离/角度，通过 MCP 开放）；③ 只给六张固定角度的 2D 渲染图。这套 A/B/C 设计直接回答一个关键问题：多给数据和工具，模型真的会变强吗？
- **确定性评分，不用 LLM 当裁判**：每道题有专家参考答案和预设规则，答案各部分分开核验再汇总。「没有『大致正确』这回事，到就是到，没到就是没到。」(来源：官方 blog / 新智元报道)
- **操作轨迹全量留档**：250 道题每道都附带专家检视操作记录，逐步保存关键帧。观察过程从「只看结论的黑箱」变成可回放的证据链——这也是未来训练数据。
- **题量分配均衡**：5 学科 × 50 题 = 250 题；建筑 CAD/机械 CAD/化学/生物/医学影像各自独立成科。

## 实用评估

### 关键数据：分数不高，反转不少

| 观察 | 数据（来源：官方 blog / 新智元报道） |
|------|------|
| 全局最高分 | 0.53，GPT-6 Astra + Codex（含部分得分） |
| 纯 2D 渲染图设置 | 最好 Claude Fable 5.1 仅 0.30；GPT-6 Astra 0.25 |
| 加工具带来的提升 | 前五名中 GPT-6.1 Sol 涨幅最大，也仅 +0.02；Claude Opus 5.5 反而 -0.02 |
| 学科分布 | GPT-6 Astra 在建筑 0.458、机械 CAD 0.580、化学 0.609 领先；生物被 Claude Fable 5.1 以 0.650 反超；医学影像 Claude Opus 5.5 以 0.399 居首 |
| 医学影像异常 | 模型操作次数约为专家 3 倍，得分却是五科最低 |

最值得记的一条：**即便在工具模式下，模型照样会去读原始坐标文件**。给它一台显微镜和一张数据表，它选数据表。这意味着当前的「3D 视觉」很大程度上是代码在解析坐标数字，而不是真的在「看」。作者自己也提醒：给三维数据后分数上去了，但这些分可能是代码从坐标算出来的，算不算「看见了」还两说。

### 什么场景值得用

- **科学 Agent / 具身系统的 eval 设计**：它的三层（只用数据 / 数据 + 工具 / 只用图像）消融结构，是任何「工具增强型视觉 Agent」都该抄的评测骨架。
- **训练环境**：确定性校验天然可转成 RL 环境，答对给奖励、答错不给，不需要另一个模型当裁判。这对做 RL 后训练的团队有直接价值。
- **过程数据**：250 道题附带的专家操作轨迹（含关键帧）可以作为「学会怎么看」的监督信号。

### 什么场景不值得用

- **通用模型选型**：250 题、专家级难度，分数区分度窄（头部模型集中在 0.3–0.5），不适合做日常排行榜汇报。
- **高频 CI 回归**：题目少且难，跑一次的信息量有限；更适合季度一次的能力摸底。
- **需要多模态通用能力的场景**：它刻意只测「科学 3D 观察」，和图表理解、文档 OCR、UI 识别没有关系。
- **成本敏感**：MCP 工具模式下的交互检视对 token 和工具调用次数消耗显著（医学影像场景模型操作次数是专家 3 倍），跑全量并不便宜。

### 迁移成本

若你要把它的评测思路接到自己的 Agent 上：核心工作量不在跑分，而在**把你领域的三维源数据接入一套可观察、可测量的查看器，并为每道题写确定性校验规则**。ScienceVision 自身花了 66 位专家 482.98 小时（化学 113h、机械 CAD 116h、医学影像 103h、建筑 77h、生物 74h）——这是自建同类基准的现实成本参照。

## 对你的意义

如果你的工作在 Agent + UI / RAG 工具链，这个 benchmark 的直接价值不在「测模型」，而在两条可迁移的工程经验：

1. **确定性校验 > LLM judge**。当评测对象是一个 Agent 的多步操作，把「答案各部分分开核验」比让另一个模型打总分可靠得多，也更便宜、更可复现。
2. **工具给了不等于会用**。加工具只涨 0.02，甚至掉分——这跟你做 RAG/工具调用时的体感一致：检索/工具接入的瓶颈往往不在工具本身，而在模型是否愿意正确地使用它。评测时应该把「是否使用了正确工具」作为独立指标，而不是只看 end-to-end 通过率。

至于「AI 科学家」这件事：建议观望。0.53 的分数不是模型不够聪明，而是「看」这件事本身还没被解决。下次有人宣布通用 Agent 可以处理工程/科研任务，让它先做完这 250 道题。
