## 是什么 / 解决什么问题

LangAlpha 的核心理念来自一个简单观察：**真实的投资研究是贝叶斯式的，不是一次性的**。你今天形成一个假设，明天新数据来了更新信念，下周财报发布再调整——这个过程持续数周甚至数月。但现有的 AI 金融工具几乎都 treating investing as one-shot：问一个问题，得到一个答案，然后对话结束。

这就像让程序员用聊天机器人写代码，但不允许保存文件、不允许版本控制、不允许在昨天的代码基础上继续工作——每次对话都是从零开始。

LangAlpha 的解法是从「vibe coding」借鉴到「vibe investing」：
- **持久化工作空间**: 每个研究目标对应一个独立 workspace（如「Q2 调仓」「数据中心需求深潜」「能源板块轮动」），所有文件、对话线程、研究产出都保存在文件系统
- **研究可累积**: 第二天回来时，昨天的分析、数据、图表都在，新分析可以建立在旧结果之上
- **程序化数据处理**: 用 PTC (Programmatic Tool Calling) 让 Agent 写 Python 代码处理财务数据，而不是把原始数据塞进 LLM 上下文——既支持复杂多步分析，又大幅降低 token 消耗

2026-04-13 发布的 v2026.04.13 版本引入了「Research Secretary」功能，让 Flash 模式可以后台调度完整的 PTC 工作空间，进一步降低了使用门槛。

## 技术架构拆解

### 核心设计决策

| 设计选择 | 理由 | 权衡 |
|----------|------|------|
| 持久化工作空间 (Per-Workspace Sandbox) | 金融研究需要状态累积，每次对话从零开始无法支持深度分析 | 增加存储开销，需要管理多个 workspace 的生命周期 |
| PTC (程序化工具调用) | 财务数据量大、计算复杂，让 LLM 直接处理原始数据既贵又容易出错 | 需要 Agent 具备代码生成和执行能力，增加系统复杂度 |
| MCP 工具渐进式发现 | 金融数据源多样（行情、财报、宏观），硬编码所有工具不现实 | 工具加载需要时间，首次使用某工具时有延迟 |
| Flash + PTC 双模式 | Flash 用于快速问答，PTC 用于深度分析，分层满足不同需求 | 用户需要理解两种模式的区别和适用场景 |
| Secretary 模式 (Human-in-the-Loop) | 后台调度 PTC 任务需要用户确认，避免资源滥用和错误方向 | 增加交互步骤，不能完全自动化 |

## 实用评估

### 什么场景值得用

1. **行业/公司深度研究**: 需要多天累积数据、写报告、反复修正观点的场景。LangAlpha 的 workspace 会保存所有中间产物，你可以随时回溯「我为什么当时看好这家公司」。

2. **季度调仓分析**: 每季度需要系统性审视持仓，LangAlpha 可以创建「Q2 Rebalance」workspace，每次分析都建立在上季度结论之上。

3. **数据密集型分析**: 需要处理多年财务数据、画图表、做回归的场景。PTC 让 Agent 写 Python 处理，token 消耗比直接喂数据低 1-2 个数量级。

4. **团队研究协作**: workspace 可以共享，多人可以在同一研究项目上累积工作（虽然目前主要是单用户设计）。

### 什么场景不值得用

1. **快速查数据**: 「AAPL 今天收盘价多少」——直接用行情 API 或财经网站更快，不需要启动 workspace。

2. **新闻阅读**: 「今天有什么重要财经新闻」——LangAlpha 不是新闻聚合器。

3. **一次性分析**: 如果你确定这个研究做完就扔，不需要后续迭代，LangAlpha 的持久化优势无法发挥。

4. **预算敏感场景**: LangAlpha 需要运行后台服务（FastAPI + PostgreSQL + Redis），自托管有基础设施成本；如果用云服务，持续运行的 workspace 会产生持续费用。

### 迁移成本

从现有工具迁移到 LangAlpha：

| 迁移来源 | 工作量 | 关键步骤 |
|----------|--------|----------|
| 手动 Excel 分析 | 中 (2-3 天) | 学习 PTC 语法，将现有 Excel 公式转为 Python 脚本，建立 workspace 结构 |

| 传统研究流程 | 高 (1-2 周) | 需要重构整个研究流程，适应「工作空间累积」范式，培训团队成员 |

## 对你的意义

如果你在构建或研究 AI Agent 框架，LangAlpha 有三个值得关注的创新点：

1. **持久化工作空间模式**: 这是 LangAlpha 最核心的贡献。它证明了「Agent + 持久化状态」比「纯对话式 Agent」更适合需要累积知识的领域。这个模式可以迁移到其他领域（法律研究、学术写作、代码维护）。

2. **PTC (程序化工具调用)**: 让 Agent 写代码处理数据而非直接处理原始数据，这是一个优雅的 token 优化方案。对于需要处理大量结构化数据的场景，这个模式值得借鉴。

3. **Secretary 模式**: Flash Agent 作为「秘书」后台调度 PTC 任务，配合 HITL (Human-in-the-Loop) 确认卡，平衡了自动化和可控性。这是 Agent 产品设计的一个好范例。

### PTC 示例（从 release notes 推断）

```python
# LangAlpha 的 PTC 让 Agent 写 Python 处理财务数据
# 而非直接把原始数据塞进 LLM 上下文

# 示例：计算某公司的自由现金流收益率
def calculate_fcf_yield(ticker: str) -> dict:
    # 从 MCP 获取财务数据
    financials = mcp.get_financials(ticker, years=5)
    
    # 程序化计算（不在 LLM 中做）
    fcf = financials['operating_cash_flow'] - financials['capex']
    market_cap = mcp.get_market_cap(ticker)
    fcf_yield = fcf / market_cap
    
    # 只返回结果给 LLM（token 高效）
    return {
        'ticker': ticker,
        'fcf_yield': fcf_yield,
        'trend': 'improving' if fcf_yield[-1] > fcf_yield[0] else 'declining'
    }
```
