## 是什么 / 解决什么问题

Hermes Agent 是由 Nous Research 开发的开源 Agent 框架，核心理念是「Agent 应该在你睡觉时也能工作，并且越用越懂你」。v0.8.0（2026 年 4 月 8 日发布）是继 v0.7.0 可插拔内存系统之后的又一次重大升级，聚焦于**智能化**和**用户体验**。

这次更新解决的核心问题有三个：

1. **长任务等待焦虑**：之前启动一个耗时任务（如 AI 模型训练、大型测试套件）后，用户需要不断轮询或保持会话等待完成通知。v0.8.0 引入 `notify_on_complete` 机制，任务完成后自动通知 Agent，用户可以离开去做别的事。

2. **模型切换成本高**：之前切换模型需要修改配置文件或重启会话。v0.8.0 实现 `/model` 命令的跨平台实时切换，支持 Telegram/Discord 内联按钮选择，且切换后保持会话连续性。

3. **工具调用不稳定**：GPT/Codex 等模型在工具调用时经常出现「描述意图但不执行」的问题。v0.8.0 通过自动化行为基准测试，自诊断并修复了 5 种失败模式，显著提升 OpenAI 模型的可靠性。

## 实用评估

### 什么场景值得用

1. **7×24 小时自动化任务**：定时报告、夜间备份、持续监控 — Hermes 的 cron 调度系统支持自然语言定义任务，完成后自动推送到指定平台。`notify_on_complete` 确保你不会错过关键结果。

2. **多模型对比评估**：需要频繁切换 GPT-5.4、Claude、Gemini、MiMo 等模型做输出对比 — `/model` 命令支持实时切换，无需重启会话或修改配置文件。

3. **跨平台协作场景**：团队使用不同消息工具（有人用 Telegram，有人用微信，有人用 Slack）— Hermes 单一网关支持 16 个平台，对话连续性跨平台保持。

4. **长期运行的研究项目**：需要 Agent 记住项目上下文、自动整理技能库 — Hermes 的自学习循环会从复杂任务中自动生成 Skill 文件，下次遇到类似问题直接调用。

### 什么场景不值得用

1. **简单一次性脚本**：如果只需要运行一个简单命令并获取结果，直接用 shell 或 Python 脚本更高效 — Hermes 的启动开销（加载配置、初始化内存等）不划算。

2. **超低延迟交互**：Hermes 的架构设计优先考虑可靠性而非延迟，端到端响应通常在 1-3 秒 — 如果需要 <500ms 的实时响应，考虑专用 API 封装。

3. **完全离线环境**：Hermes 依赖 LLM API（虽然支持本地 Ollama，但核心功能如技能生成、记忆压缩需要云端模型）— 纯离线场景功能受限。

4. **单一平台轻量使用**：如果只需要在 Telegram 上跑几个简单命令，Hermes 的完整功能集可能过于重量级 — 考虑轻量级 bot 框架。

### 迁移成本

**从 OpenClaw 迁移**：
- Hermes 提供 `hermes claw migrate` 命令，自动导入 SOUL.md、MEMORY.md、Skills、API Keys、消息平台配置
- 支持 `--dry-run` 预览迁移内容，`--preset user-data` 仅迁移用户数据不含密钥
- 迁移后用户技能存放在 `~/.hermes/skills/openclaw-imports/`

**从其他 Agent 框架迁移**：
- 配置文件：需要重写为 Hermes 的 YAML 格式（提供商、模型、工具配置）
- 技能系统：自定义工具需要适配 Hermes 的 Tool ABC 接口
- 消息平台：需要重新配置 webhook 或 bot token
- 预估工作量：简单配置 1-2 小时，复杂技能集成 1-3 天

### 实时模型切换命令

```bash

/model openai:gpt-5.4
/model anthropic:claude-sonnet-4.6
/model nous-portal:mimo-v2-pro

# Telegram/Discord 内联按钮
# 发送 /model 后显示可选模型列表，点击即切换
```

```yaml
providers:
  openai:
    credential_pool:
      - api_key: sk-xxx1
```
